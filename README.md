# buildthaw

Clear TypeScript build-info caches in one local command, while keeping your source and compiled outputs.

For developers whose incremental typecheck keeps an old error—or misses a new one—until `.tsbuildinfo` is removed. Three recent, independent reports and the alternatives are documented in [the problem research](docs/problem.md). [中文讲解](docs/guide.zh-CN.md).

## Install

Python **3.10+**; no runtime dependencies, Node installation, account, or network connection required.

Run directly from this checkout, or copy the single `buildthaw.py` file somewhere convenient:

```sh
python3 buildthaw.py /path/to/project --apply
```

If you prefer an installed command, install this local source package with pip:

```sh
python3 -m pip install --no-deps .
buildthaw /path/to/project --apply
```

Pip may need to obtain setuptools to build the package. The direct script works entirely offline and needs no installer. This project has not been published to a package registry.

## Minimal example

Preview first; without `--apply`, no files change:

```sh
python3 buildthaw.py /path/to/project
```

```text
CACHE ".cache/tsconfig.tsbuildinfo" (TypeScript 7.0.2)
1 cache(s); preview only. Use --apply to remove.
```

Clear the caches in one command:

```sh
python3 buildthaw.py /path/to/project --apply
```

```text
CACHE ".cache/tsconfig.tsbuildinfo" (TypeScript 7.0.2)
REMOVED ".cache/tsconfig.tsbuildinfo"
Removed 1 cache(s). Run your usual typecheck/build again.
```

Then run your existing typecheck or build command. Buildthaw only resets the caches; it does not run the compiler or change its configuration. Stop active build/watch processes before clearing caches.

## Select an unusual cache

Discovery recursively finds regular files ending in `.tsbuildinfo`, including hidden cache directories. It skips `node_modules`, `.git`, `.hg`, `.svn`, `.venv`, `venv`, and `__pycache__` at every depth, and does not follow symbolic links inside the root. It does not interpret `.gitignore`.

Use `--cache` for a custom filename or a cache inside an excluded directory, such as Vitest's build info:

```sh
python3 buildthaw.py /path/to/project --apply \
  --cache node_modules/vitest/dist/tsconfig.tmp.tsbuildinfo \
  --cache ".cache/custom build state"
```

Supplying `--cache` **replaces automatic discovery**. Repeat it to select multiple files; duplicate paths are removed once. Relative paths are relative to the project root, not the shell's working directory. Absolute paths are accepted only inside that root. Paths containing `..` or symbolic links are refused. Without a root argument, the current directory is used.

## What is checked

Every selected file is read and checked before any deletion begins. Buildthaw recognizes modern flat build-info JSON (`version`, `fileNames`, `fileInfos`) and the reduced build-mode format (`version`, string-valued `root` entries), including the formats generated by TypeScript 7.0.2.

It refuses unreadable files/directories, nonregular files, malformed UTF-8/JSON, duplicate JSON keys, nonstandard numeric constants, JSON nesting above 64, files above 64 MiB, and unrecognized build-info shapes. Paths in output are JSON-quoted so spaces and control characters are unambiguous. No source files, environment variables, configuration files, or credentials are inspected by the tool.

| Exit | Meaning |
| --- | --- |
| `0` | Preview completed, or all selected caches were removed; zero candidates also succeeds. |
| `2` | Invalid arguments, failed preflight, or a deletion failure. Read stderr for the path and reason. |

A preflight error removes nothing. Deletion itself is not transactional: if permissions change or an unlink fails partway through, completed deletions are listed and the error reports how many caches were already removed.

## Limits and alternatives

- This is a cache reset, not a compiler fix or a stale-cache detector. Every recognized selected cache is removed, even if it was valid. The next check may take longer.
- Use an idle, trusted project tree. There is no filesystem lock or protection against concurrent path/content replacement. Preview and apply are separate scans. Deletions have no undo operation; normal builds regenerate the caches.
- JSON structure is a plausibility check, not proof that TypeScript created a file. Older nested `program` formats and future unrecognized formats are refused. There is no force-delete escape hatch.
- It does not resolve tsconfig inheritance or project references. Caches outside the supplied root are not cleared; custom filenames and excluded directories require explicit selection. Corrupt caches need manual investigation/removal.
- Verified on Linux with Python 3.14.4 and TypeScript 7.0.2. Windows junction/reparse-point handling is not supported; use this release on POSIX systems.
- If you know one cache path, deleting it manually is simpler. If rebuilding immediately is acceptable, `tsc -b --force` is an existing solution. `tsc -b --clean` also removes compiled outputs. Buildthaw is useful when you want a checked cache-only sweep without maintaining shell globs.

## Development and verification

```sh
python3 -m unittest discover -s tests -v
```

Tests exercise the real CLI in subprocesses and use temporary fixtures only under `.test-tmp/` in this checkout. POSIX permission tests require a non-root user. One optional integration test uses an official TypeScript 7.0.2 Linux x64 compiler at `.tools/typescript-native/package/lib/tsc`; it is skipped if that dependency is absent. No test downloads anything.

To run that integration test on a fresh Linux x64 checkout, obtain `@typescript/typescript-linux-x64@7.0.2` from the official npm registry, verify its published integrity, and extract its `package/` directory under `.tools/typescript-native/`. The compiler is a development-only dependency and is not bundled with buildthaw.

The delivery run included this compiler: incremental, composite, and ordinary build-mode caches were removed, output bytes and timestamps stayed unchanged, and a subsequent build recreated the caches. The original stale-error reproduction also changed from exit `1` to exit `0` after clearing the cache, with no further source edits: [recorded results](docs/research/reproduction.json). The chronological red/green record is in [docs/tdd-log.md](docs/tdd-log.md).
